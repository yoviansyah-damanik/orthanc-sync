Panduan Pengoperasian Orthanc Bridge

Halaman ini menyediakan petunjuk komprehensif mengenai cara kerja integrasi PACS/DICOM, konfigurasi alat pemeriksaan (modality), diagnosa mandiri, serta solusi pemecahan masalah klinis.

Alur Siklus DICOM Worklist

Pilih tahapan di bawah ini untuk melihat detail petunjuk pengoperasian klinis masing-masing langkah.

1

Pendaftaran Pasien di SIMRS

Proses dimulai ketika staf administrasi mendaftarkan pasien untuk pemeriksaan penunjang radiologi melalui **SIMRS (Sistem Informasi Manajemen Rumah Sakit)**. SIMRS akan menghasilkan data registrasi beserta nomor antrean pemeriksaan yang unik.

Standard Operating Procedure (SOP): Pastikan **Accession Number** yang di-generate oleh SIMRS bersifat unik dan tidak duplikat dengan pemeriksaan masa lalu untuk mencegah penimpaan file DICOM lama di server.
2

Otomatisasi File DICOM Worklist (.wl)

Setelah pasien didaftarkan, SIMRS memicu REST API Orthanc Bridge (secara otomatis di latar belakang). Sistem Orthanc Bridge akan langsung menerjemahkan payload JSON tersebut menjadi struktur file DICOM fisik dengan ekstensi `.wl`, kemudian menyimpannya langsung pada direktori penyimpanan lokal yang telah dikonfigurasi.

Informasi Teknis: Aplikasi menyaring nama pasien ke dalam format penamaan DICOM standar (Huruf Kapital, tanda penyambung ^) secara otomatis untuk menaati ketentuan internasional DICOM.
3

Penarikan Data (Query) di Alat Radiologi

Di ruang pemeriksaan, Radiografer/Teknisi tidak perlu lagi mengetik ulang nama pasien pada layar alat pemeriksaan (Modality: USG, X-Ray, CT, dll.). Cukup menekan tombol **"Worklist Query"** atau memasukkan *Patient ID* / *Accession Number* di alat tersebut. Alat akan mengirim query DICOM MWL ke server Orthanc, dan server Orthanc akan menyajikan daftar pasien secara instan dari file fisik `.wl` yang disuplai oleh Orthanc Bridge.

Petunjuk Klinis: Metode ini 100% meminimalisasi kesalahan ketik nama pasien (human error) yang dapat berakibat fatal pada tertukarnya data rekam medis radiologi.
4

Proses Scanning & Pengiriman Gambar ke PACS

Radiografer memilih entri pasien yang sesuai pada daftar modality, lalu melakukan tindakan pemindaian medis (*scanning*). Setelah pemindaian selesai, alat modality akan mengirimkan (*C-STORE*) file gambar DICOM medis yang dihasilkan secara otomatis ke server **Orthanc PACS**.

Catatan Penting: Pastikan koneksi jaringan alat modality ke IP Orthanc PACS berstatus tersambung secara stabil untuk kelancaran transfer gambar klinis berukuran besar.
5

Pemberitahuan Selesai (Callback Webhook)

Setelah Orthanc PACS sukses mendeteksi masuknya seluruh rangkaian gambar pemeriksaan medis (*study*), sistem Orthanc Bridge akan secara berkala mencocokkan *study* tersebut dengan antrean worklist. Saat data cocok, Orthanc Bridge akan memicu panggilan **Webhook Callback** ke SIMRS untuk memberitahukan bahwa proses scanning telah sukses diselesaikan dan siap untuk dibaca oleh dokter spesialis radiologi (Sp.Rad).

Status Sinkronisasi: Anda dapat memonitor log webhook klinis ini secara detail pada menu **API Log** di sidebar kiri.

Sistem Webhook Callback

Webhook difungsikan sebagai sistem umpan balik asinkron dari Orthanc Bridge kembali ke SIMRS atau sistem eksternal klinis lainnya. Setiap siklus pembuatan worklist — baik yang berhasil maupun yang gagal — dapat secara otomatis memicu notifikasi langsung ke URL tujuan yang telah dikonfigurasi.

Skenario Pemanfaatan Webhook

Notifikasi Sukses

Saat file worklist .wl sukses ditulis di disk dan tercatat di database, sistem langsung mengirimkan HTTP POST ke URL webhook untuk memberi tahu bahwa antrean pasien di PACS telah aktif dan siap dipanggil alat modality.

Notifikasi Kegagalan (Error Callback)

Jika terjadi kegagalan teknis — misalnya format JSON tidak valid, duplikasi nomor accession, atau folder penyimpanan terkunci — sistem mengirimkan payload kegagalan agar SIMRS dapat segera mencatat status gagal tanpa memblokir antrean utama.

Hierarki Penentuan URL Webhook

Prioritas 1
Dynamic Webhook — SIMRS mengirimkan parameter "webhook_url" langsung pada setiap payload JSON request. Sistem akan memprioritaskan URL ini, ideal untuk callback yang berbeda-beda per poli/jenis pemeriksaan.
Prioritas 2
Default Webhook (Level API Key) — Administrator mendaftarkan URL callback bawaan pada saat membuat API Key di menu Manajemen API. Digunakan sebagai fallback jika SIMRS tidak mengirimkan URL secara eksplisit.

Struktur Payload yang Dikirimkan

Payload Sukses — HTTP POST 
"accession_number": "RAD20240001",
"status": "Sukses",
"message": "Worklist berhasil dibuat"
// Atau: "Worklist berhasil diupdate"
Payload Gagal — HTTP POST 
"accession_number": "RAD20240001",
"status": "Gagal",
"message": "Deskripsi kesalahan teknis..."
// Jika acc. tidak dikenal: "UNKNOWN"
Pelacakan via API Log: Setiap upaya pengiriman webhook dicatat pada tabel WorklistLog. Jika server target SIMRS mati atau diblokir firewall, lacak detail kegagalan pengiriman melalui menu API Log di sidebar kiri.

Pemecahan Masalah Klinis (Troubleshooting)

* Periksa apakah nama file fisik `.wl` yang bersangkutan terbuat di direktori server utama. Anda dapat memindainya langsung via tombol **Check Worklist File** di menu Petunjuk API. * Pastikan pengaturan AE Title, IP Address, dan Port pada alat modality radiologi telah terkonfigurasi dengan tepat menyasar ke server Orthanc. * Periksa apakah direktori folder penyimpanan file `WORKLIST_DIR` memiliki izin akses tulis yang aktif. Jika belum, Anda dapat menekan tombol **"Beri Izin Akses"** pada menu Konfigurasi.
* Pastikan layanan server utama **Orthanc PACS** saat ini berjalan aktif dan normal (bukan dalam keadaan mati / *down*). * Verifikasi parameter otentikasi (URL Orthanc, Username, dan Password) pada menu **Konfigurasi** sudah sesuai dengan data kredensial akses server PACS Anda. * Klik tombol **"Tes Koneksi Orthanc"** di menu Konfigurasi untuk memicu peninjauan teknis instan.
* Periksa log pengiriman secara real-time pada menu **API Log** untuk memvalidasi detail status pemanggilan server, error response, atau payload yang dikirim. * Pastikan alamat domain server target `webhook_url` yang disuplai oleh SIMRS saat pendaftaran berstatus aktif, dapat dijangkau dari server lokal, dan tidak terhalang oleh sistem firewall jaringan rumah sakit.
